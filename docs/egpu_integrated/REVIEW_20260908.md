## Fact: interpretation of offline evidence

`ROOT_CAUSE` is a request to investigate evidence or state inconsistencies; it
does not establish a physical cause. Supply/link telemetry and BIG exceptions
can coincide without establishing causation. Queue counts are input-event
counts, not independent incident counts or confirmed ground truth.

`sameFrameOutputPreserved` describes output evidence only: matching frame ID,
nonstale known age, and explicit finite-output evidence. Unknown output identity
or finiteness produces `null`. A verified output can coexist with an inconsistent
latch, which still receives `ROOT_CAUSE`; it grants no runtime approval.

Rows that need restart handling carry `processId` on every row and set
`restartBoundary=true` only when entering a new, previously unseen process ID.
Both trackers reset at that boundary. These are exporter assertions; synthetic
tests do not prove that a real device restarted.

Effective Guardian and temporal policy values are included in output. Previously
inline standstill/creep heuristic values are now named policy fields without
changing their values. No new vehicle safety threshold has been introduced.
