# 조향 응답 검증 도구

기록된 조향 명령으로 실제 측정 조향각을 재현할 수 있는지 확인하는 **오프라인 진단 도구**입니다. 차량 제어기, 파라미터 추천기, 실제 차량에 적용할 응답 모델이 아닙니다. CAN 송신·차량 설정 변경 기능이 없습니다.

## 실행

Python 3.12 이상과 `numpy`, `zstandard`, `pycapnp==2.1.0`이 필요합니다. `--source`에는 전체 `openpilot/cereal/log.capnp`와 `opendbc_repo/opendbc/car`를 가진 소스 경로를 지정합니다. `--logs`는 한 주행의 `*--<segment>/rlog.zst` 디렉터리들을 포함해야 합니다.

```bash
python tools/steering_response/assess.py \
  --logs /private/route \
  --source /path/to/openpilot \
  --train-end 45 --validation-end 68 \
  --output /private/results/steering-response.json

python -m unittest discover -s tools/steering_response/tests
```

구간 0–45로 계수를 학습하고, 46–68로 모델을 선택하고, 69 이후는 최종 평가에만 사용합니다. 경계는 실행 전에 정해야 합니다. 차량이나 결과에 맞춰 최종 평가 구간을 다시 고르면 새로운 검증 자료가 필요합니다. 학습/선택/평가 표본은 같은 주행에 속할 수 있으므로 독립된 주행들의 통계로 해석하지 않습니다.

출력 JSON에는 사적인 주행 분석 자료가 포함됩니다. 원본 로그, 결과 JSON, 차량 설정, 식별자는 공개 저장소에 커밋하지 마세요. 실패한 구간도 목록과 사유를 기록합니다.

## 신호와 선별

- 출력: `carState.steeringAngleDeg`의 측정 핸들 각도(도). 차량 위치나 차선 여유거리는 아닙니다.
- 입력: `carOutput.actuatorsOutput.torque`의 소프트웨어 적용 명령. EPS의 실제 발생 토크를 측정한 값이 아닙니다.
- 속도/roll은 기록된 궤적을 조건으로 사용합니다. 미래 속도나 도로 기울기를 별도로 예측하는 모델이 아닙니다.
- 20 Hz 격자에 과거 메시지만 결합합니다. 기본 명령은 직전 50 ms 동안의 시간 가중 평균으로, 원래 약 100 Hz 명령 변화를 적분합니다. `--input-mode last`는 마지막 표본 유지 방식의 민감도 비교입니다.
- 8–40 m/s, 조향 활성 상태, CAN/센서 유효 상태를 사용합니다. 운전자 조향 개입, 페달 입력, 방향지시등, 조향 오류, 절대 명령 0.98 이상은 제외합니다. 자동 감속 자체는 제외하지 않습니다. 변화율 제한에 걸린 명령은 적용된 입력이므로 그대로 사용합니다.
- raw driver torque 절댓값 한계 50이 주 평가, 30·100은 선별 민감도입니다. 핸들 접촉 유무를 이 숫자만으로 판정하지 않습니다. 50 ms 사이의 짧은 초과도 보존합니다.
- 약 6.05초의 겹치지 않는 블록에서 초기 각도와 5초 후까지의 응답을 비교합니다. 구간 경계·누락·선별 탈락을 연결하지 않습니다. 따라서 적격 표본 시간과 실제 평가 시간은 다릅니다.

## 계산과 판정

안정적인 1차 응답의 시간상수 7개, 기록 신호 지연 8개를 조합합니다. 각 후보의 계수는 학습 자료만으로 구합니다. 검증 자료의 전체 응답 RMSE로 선택하며 최종 평가 자료로 후보를 선택하지 않습니다. 예측을 시작한 뒤 실제 조향각을 다시 주입하지 않습니다.

기본 `--response-mode absolute`는 기존 절대 조향각 응답을 유지합니다. 선택 옵션 `--response-mode anchored`는 초기 측정 각도를 기준으로, 지연을 반영한 초기 입력과 이후 입력의 차이에 대한 응답만 더합니다. 명령×속도 항도 곱을 계산한 뒤 초기 값과의 차이를 사용하며, 명령 없는 비교 모델에도 같은 방식을 적용합니다. 이 방식은 초기 각도가 초기 입력의 국소 평형에 있다고 가정하고, 이미 진행 중인 과도 응답이나 초기 각속도를 별도로 반영하지 않습니다. 입력이 일정하면 초기 각도를 그대로 유지합니다. 미래 측정 조향각은 예측에 사용하지 않으며, 이 옵션의 결과도 Kp 변경 효과를 검증하지 않습니다. 사용 방식은 평가 전에 정하고 결과를 본 뒤 최종 평가 자료에 맞춰 고르지 않습니다.

동일한 속도·roll 항을 가지되 조향 명령 항만 제거한 모델과 비교합니다. 현재 각도 유지, 초기 각속도 유지 기준도 함께 기록합니다. 시간상수·지연은 이 모델에서 선택된 숫자일 뿐, EPS의 물리적인 지연이나 차량 기본값이 아닙니다.

`PREDICTION_SCREEN_FAILED`는 다음 중 하나라도 성립한 경우입니다.

- 검증 또는 최종 평가 RMSE가 명령 없는 모델보다 20% 이상 개선되지 않음.
- 0.25/0.5/1초에서 명령 없는 모델과 현재 각도 유지 기준 중 더 나은 기준을 이기지 못함.
- 검증 또는 최종 평가에 실제 사용한 속도 표본의 5%를 초과하는 표본이 학습 속도 범위를 벗어남. 예측에 사용하지 않은 앞뒤 여유 표본은 이 범위를 넓히지 않습니다.

20%와 5%는 이 도구의 사전 지정 선별 기준이며 안전 인증 기준이 아닙니다. 통과해도 `controller_comparison=NOT_VALIDATED`입니다. 피드백 중 수집된 명령은 차량 오차와 연관되어 있어 예측 적중만으로 변경된 제어기의 인과 효과를 증명할 수 없습니다. 원래 제어기의 피드백·적분항·CAN 제한까지 포함한 별도 검증 없이 Kp 변경 효과나 차선 유지 개선을 출력하지 않습니다.

자료 부족은 `INSUFFICIENT_WINDOWS`로 보고합니다. 이 도구의 모델이 실패했다는 사실이 모든 종류의 차량 모델이나 모든 기존 로그가 사용할 수 없다는 뜻은 아닙니다.
